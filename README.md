# Сквозной RAG-проект по курсу GIGASCHOOL

Этот репозиторий содержит сквозной учебный проект по созданию RAG-системы по
курсу «LLM-инженер» от GIGASCHOOL. Задача проекта — реализация первичного этапа видеоиндексации, суть которого заключается в формировании текстовых описаний одного статичного кадра и retrieval таких камер, которые удовлетворяют запросу (наличие определенных объектов в кадре, качество изображения, погода, освещение и т.д.).

Проект охватывает подготовку структурированной разметки, проверку качества, chunking, EDA, построение retrieval baseline и оформление
экспериментов в Colab-совместимых notebooks.

## Данные

Готовые версии датасета следует загружать из
[mairon2300/video_retrieval](https://huggingface.co/datasets/mairon2300/video_retrieval),
а не пересобирать без необходимости из исходных экспериментальных артефактов.

Все локальные датасеты и изображения должны находиться в `hf/`. Ожидаемая
структура для версии vX:

```text
hf/
├── images/
│   └── pilot-500-v1/
└── vX/
    ├── annotations/
    │   ├── gt/
    │   └── vlm_inferred/
    ├── offline_chunking/
    ├── prompts/
    ├── provenance/
    ├── manifest.json
    └── README.md
```

`hf/vX` содержит готовую разметку и материализованные chunks. Изображения
хранятся отдельно в `hf/images/pilot-500-v1` и не содержатся в репозитории.

Здесь и далее `vX` — шаблон имени версии, где `X` является целым числом:
например, `v0`, `v1` или `v2`. Буквальной директории `vX` создавать не нужно.
Текущая реализация проекта и опубликованный первый release используют `v0`.

## Установка

Из корня репозитория:

```bash
python -m pip install -e .
```

Проект устанавливается как пакет `gigaschool-video-rag`, а импортируется под
именем `gigaschool_rag`. Контракты разных версий изолированы друг от друга:

```python
from gigaschool_rag.versions.v0 import dataset_root
```

При добавлении новой версии нужно создать отдельный модуль
`gigaschool_rag.versions.vX`, а не менять контракт уже опубликованной версии.

## Структура репозитория

### `build_rag_dataset/vX/`

Version-specific утилиты для создания и проверки **новой версии датасета**.
Текущая автономная сборка находится в `build_rag_dataset/v0/`:

- `build_all.py` выполняет полный pipeline в правильной последовательности;
- `generate_descriptions.py` и `verify_descriptions.py` вызывают producer и
  verifier через Cursor SDK, если передан каталог изображений;
- `build_dataset.py` собирает release v0 из созданных или сохранённых
  producer/verifier records,
  ontology и agreement-результатов, нормализует факты и разделяет их на trusted
  и untrusted;
- `build_fact_chunks.py` детерминированно строит представление
  «один структурированный факт — один chunk»;
- `validate_dataset.py` проверяет количество записей, уникальность фактов,
  trusted/untrusted partition и соответствие chunks исходным facts.

Эти скрипты не требуются для обычной работы с уже опубликованным датасетом.
Они нужны при изменении исходной разметки, trust policy или формата новой
версии. В `build_rag_dataset/v0/input/` находится минимальный набор исходной
разметки для автономной пересборки без папки `rag/`. Полный режим принимает
изображения через `--images-root /path/to/pilot-500-v1`; offline-режим
использует зафиксированные VLM-ответы. Результат создаётся в
`build_rag_dataset/v0/output/`.

### `eda/vX/`

Это шаблон расположения version-specific EDA; текущий скрипт находится в
`eda/v0/run_eda.py`. Он выполняет исследовательский анализ нечанкированных
VLM-описаний:

- считает распределения длины и количества фактов;
- оценивает технический шум;
- ищет точные и близкие дубликаты;
- строит TF-IDF/KMeans-кластеры тематик;
- сохраняет численные результаты и интерактивные Plotly-графики в
  `eda/vX/output/`.

Содержимое `eda/vX/output/` является регенерируемым и игнорируется Git.

### `evaluation/vX/`

Это шаблон расположения version-specific evaluation; текущий скрипт находится
в `evaluation/v0/evaluate_fact_retrieval.py`. Он явно импортирует контракт
`gigaschool_rag.versions.v0` и запускает воспроизводимый TF-IDF baseline по
trusted fact chunks. Для каждого label он строит текстовый запрос, ранжирует
изображения и рассчитывает precision, recall, F1 и average precision.
Сгенерированные evaluation-артефакты сохраняются рядом со скриптом.

### `notebooks/vX/`

Это шаблон расположения version-specific notebooks. Текущий
`notebooks/v0/control_point_1_v0.ipynb` — Colab-совместимый notebook первой
контрольной точки. Он описывает задачу, происхождение producer/verifier-разметки,
EDA, подготовку корпуса и базовые retrieval-эксперименты.

Notebook является самостоятельным: он не должен импортировать или запускать
Python-скрипты из своей директории. Локальные `.py`-генераторы notebook
игнорируются Git; при необходимости notebook может использовать публичные
скрипты верхнего уровня проекта.

### `hf/`

Единое место для готовых версий датасета и соответствующих изображений.
Внутренний `README.md` каждой версии документирует её schema, семантику полей,
provenance и ограничения.

### `src/gigaschool_rag/`

Устанавливаемый Python-пакет проекта. Подпакет `versions/` содержит неизменяемые
контракты конкретных версий: идентификаторы schema и правила построения путей к
dataset, images, EDA и evaluation. Скрипты версии v0 должны импортировать эти
значения только из `gigaschool_rag.versions.v0`.

Переиспользуемая логика v0 также находится в пакете:

- `gigaschool_rag.versions.v0.eda` — расчёт и сохранение EDA;
- `gigaschool_rag.versions.v0.evaluation` — канонический gold, rejected
  candidates и TF-IDF evaluation;
- `gigaschool_rag.versions.v0.resources` — неизменяемые versioned evaluation
  resources, доступные через `importlib.resources`.

Скрипты в `eda/v0/` и `evaluation/v0/` являются тонкими CLI entrypoints поверх
этого API. Notebook импортирует тот же API, поэтому локальный запуск и Colab не
дублируют вычислительную логику и не зависят от расположения checkout.

## Типовой порядок работы

1. Установить проект командой `python -m pip install -e .`.
2. Загрузить готовую версию датасета с Hugging Face в `hf/`.
3. Разместить изображения в соответствующей подпапке `hf/images/`.
4. Выполнить EDA или открыть готовый notebook.
5. Запустить retrieval/evaluation experiments.
6. Использовать `build_rag_dataset/vX/` только при подготовке новой версии
   датасета.
